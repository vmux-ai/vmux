# Browser

Use the Browser to gather context, inspect the product, and keep references beside the work that needs them.

## Browse alongside a task

Open a site or search through the address/navigation controls. Keep documentation, an issue, or the running product in a pane beside a Session or Code. Tabs and page history let you return to a useful reference without replacing the rest of the workspace.

For an investigation, identify the page and behavior you want the agent to inspect. Keep the relevant Project and Session visible so observations can become a focused implementation or answer.

## Connect browsing to code

A practical loop is to reproduce the behavior in the Browser, inspect the owning code, make a change, and refresh or revisit the page to check the result. Terminal can keep the development server running while Browser shows its output.

Review the final behavior yourself when the task requires app QA. A code change and a passing test are useful evidence; the visible result is the next checkpoint when appearance or interaction matters.

## Know which surface you are using

Web pages are ordinary browser content. Native Vmux pages provide capabilities such as Code, Git, Terminal, and Session through the same workspace navigation. Web content does not gain unrestricted machine access by being open beside those pages.

Keep permission requests associated with the task that needs them. Browser extensions and native tools use their own supported boundaries.
